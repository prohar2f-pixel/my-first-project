## ЧАСТЬ 1: Критика idea.md

### Настоящая боль vs то что написано

**Настоящая боль одна:** "я трачу слишком много времени на написание постов, и мне не хватает идей."

Что реально решает эту боль:
- ✅ Claude генерирует черновик → ты жмёшь кнопку → пост улетел в канал
- ✅ Бот предлагает идеи для сценариев видео

Что **НЕ решает боль**, а создаёт новую сложность:

| Фича из idea.md | Проблема |
|----------------|----------|
| Автоматический анализ конкурентов | Как? Telegram-каналы закрыты без авторизации. VK — серая зона. Это отдельный продукт на 2-4 недели |
| Сбор трендов из интернета | Через что конкретно? RSS? Google Trends (неофициальный)? Tavily API? Каждый вариант = отдельная интеграция |
| Аналитика просмотров/лайков | VK API требует отдельных прав. Telegram не отдаёт статистику каналов через Bot API |
| Связь постов с заявками в @prohar_tz_bot | При 2-3 постах/неделю и 1-2 заявках/месяц — статистически бессмысленно. Это стартаперская фича |

**Приговор:** 60% идеи — это Phase 3, написанный как Phase 1.

---

### Противоречие #1: "Аудитория — все подряд" + вирусный контент

Вирусность берётся из специфичности. "Как я сделал бота для стоматологии и им стало +40 заявок/день" — вирусно. "5 причин сделать сайт" — нет.

Без конкретной ниши Claude будет генерировать шаблонный корпоративный текст. Ты будешь тратить больше времени на правки, чем на написание с нуля.

**Нужно решить до спецификации:** для кого именно ты пишешь? Малый бизнес? Рестораны? Медицина? Или "фрилансер, который ищет любых клиентов" — тогда аудитория контента это другие фрилансеры (партнёрство, не клиенты).

---

### Противоречие #2: "Писать в моём стиле" — механизма нет

Как бот узнает твой стиль? Claude без примеров пишет нейтральный корпоративный текст.

Нужно одно из двух:
- Загрузить 10–20 реальных твоих постов как образцы стиля в базу
- Написать system prompt с описанием твоего голоса: "пиши коротко, без воды, с конкретными цифрами, от первого лица"

В idea.md этого нет. Без этого бот бесполезен.

---

### Что забыто в idea.md

1. **Изображения** — не упомянуты вообще. Посты в VK без картинок теряют охват. Генерация изображений = DALL-E ($0.04/шт) или шаблоны через Pillow. Это продуктовое решение, его нет в идее.

2. **Бот должен быть администратором канала** — без прав администратора в Telegram-канале бот не может публиковать. 30 секунд настройки, но нужно явно указать в спецификации.

3. **Как работает кнопка "Изменить"?** Пользователь нажал ✏️ — что дальше? Пишет инструкцию? Claude перегенерирует? Это целый UX-сценарий (FSM — машина состояний), который нигде не описан. Разработчик будет придумывать на ходу.

4. **Очередь публикаций** — одобрил 3 поста сразу. Они публикуются немедленно все три? Или по расписанию? Как настраивать расписание?

5. **VK-токены истекают** — через несколько часов/дней без refreshFlow посты в VK молча перестанут публиковаться. Бот не упадёт, просто ничего не будет происходить.

6. **"Мощная система памяти"** — ни разу не объяснено что именно. Это 4 принципиально разных вещи (см. часть 3).

## ЧАСТЬ 3: Технический разбор

### Что реально простое (1 неделя)
Генерация → одобрение кнопкой → публикация в Telegram-канал. Это 200-300 строк Python.

### Что сложнее чем кажется

**VK API — не тривиально:**
- Токен истекает, нужен refresh
- Лимит: максимум 3 поста в одну группу в час
- Автоматизация всё жёстче блокируется VK
- Срок разработки: 3-5 дней + постоянная поддержка
- Обязательно: при любой ошибке VK — немедленный алерт в Telegram, иначе посты молча не публикуются

**Instagram — не включать в спецификацию вообще:**
- Нужен Meta Business аккаунт + Facebook App + App Review (недели ожидания)
- Токены истекают каждые 60 дней, нужен re-auth flow
- Требуется публично доступный HTTPS callback URL
- Ограниченные типы контента через API
- Решение: вынести в отдельный документ "исследовать отдельно, когда понадобится"

**Анализ конкурентов — отдельный продукт:**
- Telegram-каналы: чтение требует MTProto (pyrogram/telethon), не Bot API
- VK: API работает, но нужны парсинг + фильтрация
- Instagram: только скрапинг, нарушает ToS
- Срок: 2-4 недели
- Решение: убрать из Phase 1. Заменить на ручной список RSS-фидов конкурентов

**Тренды из интернета — есть рабочее решение:**
RSS с vc.ru, habr.com + Tavily API для живого поиска. Стоимость ~$5-10/месяц. Это реализуемо.

### Стоимость Claude API

При 10 постах/месяц (2-3 в неделю) + claude-sonnet-4-6:
- ~$0.17/месяц на генерацию
- Даже с контекстом трендов и памяти: до $2/месяц
- **API-стоимость не является проблемой для этого проекта**

### SQLite на Windows VPS — работает, но требует настройки
```python
# Обязательно при инициализации БД:
await db.execute("PRAGMA journal_mode=WAL")
await db.execute("PRAGMA synchronous=NORMAL")
# Использовать aiosqlite, не синхронный sqlite3
```
Без WAL-режима на Windows будут ошибки "database is locked".

### apscheduler на Windows
- Использовать `AsyncIOScheduler` (не ProcessPool) — без fork/spawn проблем
- Обязательно: персистентное хранилище задач в SQLite
- Без этого после перезагрузки сервера все запланированные посты теряются

### "Мощная система памяти" — нужно выбрать конкретный тип

Это 4 принципиально разных вещи:

| Тип | Что делает | Сложность |
|-----|-----------|-----------|
| A: История постов | "Не повторяй темы последних 30 дней" | 1 день |
| B: Обратная связь | "Посты про ИИ работают лучше, давай больше" | 3-5 дней |
| C: Стиль и голос | Сохранённые примеры твоих постов в system prompt | 2 дня |
| D: Семантическая память | RAG + векторная БД, поиск по смыслу | 1-2 недели |

Для MVP достаточно A + C. "Мощная система памяти" как написано = разработчик сразу строит D и теряет 2 недели.

## ТОП-12 РЕКОМЕНДАЦИЙ ДЛЯ СПЕЦИФИКАЦИИ

### 🔴 Критично — без этого не стартовать

**1. Определить "стиль" до разработки**
Собрать 10-15 реальных постов Александра (из любых соцсетей). Это войдёт в system prompt как образцы. Без этого бот пишет не твоим голосом.

**2. Спроектировать FSM для кнопки "Изменить"**
Нарисовать полный сценарий: нажал ✏️ → что бот спрашивает → как пользователь отвечает → как Claude получает инструкцию → как сохраняется состояние → таймаут если ушёл. Это сделать ДО кода, иначе переписывать на ходу.

**3. Контракт на обработку ошибок**
Правило одно: любая внешняя ошибка (VK API, Claude API, планировщик) → немедленный алерт в Telegram администратору. Никаких молчаливых сбоев.

**4. Выбрать тип памяти явно**
В спецификации написать: "Бот помнит темы последних 30 дней (тип A) + хранит 5 последних одобренных постов как примеры стиля (тип C)." Не "мощная система памяти."

**5. Принять решение по изображениям**
Либо: "Phase 1 — только текстовые посты" (просто, быстро).
Либо: "Phase 1 — шаблоны через Pillow с логотипом" (2 дня работы).
Нельзя оставить открытым.

### 🟡 Важно — иначе будут проблемы

**6. VK refresh flow обязателен**
Токен VK должен обновляться. Без этого через несколько дней/недель посты в VK молча прекратятся.

**7. Убрать Instagram из спецификации**
Заменить на: "Instagram — исследовать отдельно, не раньше чем Phase 1 будет в продакшне 2 месяца."

**8. Анализ конкурентов → ручной список RSS**
Вместо "автоматический анализ конкурентов" написать: "Администратор вручную добавляет список Telegram-каналов и VK-групп конкурентов. Бот парсит их последние 10 постов как контекст для генерации." Это реализуемо за 1 день.

**9. Очередь публикаций с расписанием**
Одобренный пост → встаёт в очередь на ближайший свободный слот (вт/чт/сб, 10:00 МСК). Пользователь может сдвинуть слот. Без этого три поста уйдут одновременно.

**10. apscheduler: персистентное хранилище**
```python
SQLAlchemyJobStore(url='sqlite:///jobs.db')
```
Обязательно, иначе после перезагрузки сервера очередь пропадает.

### 🟢 Для качества продукта

**11. "Show, don't tell" в первом сообщении**
```
/start → "Привет! Этот бот — живой пример того, что строит Александр.
За 2 дня. На Python. Посмотри что умею 👇"
[🌐 Сайты] [🤖 Боты] [⚡ ИИ-агенты] [📁 Кейсы] [✍️ Заказать]
```
Бот сам является портфолио.

**12. Лимит regenerate = 3**
После 3 нажатий "Перегенерировать" бот предлагает: "Давай попробуем другую тему?" и предлагает выбор из 3 новых тем. Задача не висит вечно.

## Финальный приговор

**Что точно строить в Phase 1 (1-2 недели):**
- Генерация поста + сценария через Claude с примерами стиля
- Approve/reject/regenerate (макс 3 попытки) с очередью
- Публикация в Telegram-канал
- Публикация в VK с refresh-токеном и алертами на ошибки
- RSS-фиды как источник трендов (3-5 источников, ручной список)
- История постов (30 дней, без повторов тем)

**Что убрать из Phase 1:**
- ❌ Автоматический анализ конкурентов
- ❌ Аналитика просмотров/лайков (добавить в Phase 2)
- ❌ Связь постов с заявками (аналитически бессмысленно при таком объёме)
- ❌ Instagram (бюрократия, добавить в Phase 3 если вообще)
- ❌ "Мощная семантическая память" (заменить на A+C, 3 дня работы)

**Ключевой инсайт:**
Ядро бота — это 1 неделя работы. Вся остальная идея — это 2-3 месяца. Построй ядро, запусти, получи первые реальные данные о том что работает, а потом расширяй. Сейчас ты знаешь что хочешь — но не знаешь что реально нужно. Это выяснится только после первых 4 недель публикаций.
