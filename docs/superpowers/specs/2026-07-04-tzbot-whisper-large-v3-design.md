# ТЗ: качественное распознавание голосовых в ТЗ-боте (Whisper large-v3 через Groq)

Дата: 04.07.2026
Проект: `tzbot/` — Telegram-бот, который интервьюирует клиентов и составляет ТЗ.
Статус: дизайн одобрен, готово к реализации.

## 1. Проблема

Бот плохо распознаёт голосовые сообщения. Причина — текущая реализация в
`main.py` (`handle_voice`, функция `transcribe`): библиотека `SpeechRecognition`
с `recognize_google` — это бесплатное легаси Google Web Speech API. Оно даёт
низкую точность на русском, не ставит пунктуацию, обрезает длинные записи и
нестабильно работает. Клиенты диктуют ответы голосом, бот их искажает, и
качество итогового ТЗ страдает.

Дополнительно: бот вообще не принимает видеокружочки — а клиенты часто
отвечают именно ими.

## 2. Цель

1. Голосовые сообщения распознаются моделью **Whisper large-v3** через
   **Groq API** — с пунктуацией и точностью уровня лучших транскрибаторов.
2. Бот распознаёт **видеокружочки** (video note) так же, как голосовые.

## 3. Решение — обзор

Groq предоставляет OpenAI-совместимый endpoint `audio/transcriptions` с
моделью `whisper-large-v3`. В боте уже используется пакет `openai` (для
OpenRouter) — добавляется второй клиент с другим `base_url`. Groq принимает
файлы OGG (голосовые) и MP4 (кружочки) напрямую, поэтому конверсия аудио и
зависимости `SpeechRecognition`, `pydub`, `ffmpeg` становятся не нужны и
удаляются.

Затрагиваются только: `main.py`, `requirements.txt`, `nixpacks.toml`,
`.env.example`, переменные окружения на Railway.

## 4. Требования

### 4.1. Конфигурация

- Новая обязательная переменная окружения `GROQ_API_KEY`
  (получить на https://console.groq.com → API Keys; бесплатно).
- Новая необязательная переменная `ASR_MODEL`, по умолчанию
  `whisper-large-v3` (по аналогии с существующей `LLM_MODEL`; позволяет
  переключиться на `whisper-large-v3-turbo` без правки кода).
- Обе переменные добавить в `.env.example` и в Railway → Variables.
- Клиент: `OpenAI(base_url="https://api.groq.com/openai/v1", api_key=GROQ_API_KEY)`.

### 4.2. Распознавание голосовых (`handle_voice`)

- Скачивание OGG-файла из Telegram — как сейчас (`download_to_memory`).
- Функция `transcribe` заменяется целиком: файл отправляется в
  `groq.audio.transcriptions.create` без какой-либо конверсии, параметры:
  - `model=ASR_MODEL`
  - `language="ru"` (фиксируем язык — исключает ошибки автоопределения)
  - `temperature=0`
  - файл передаётся с именем и расширением (например `("voice.ogg", buf)`),
    иначе API не определит формат.
- Поведение после распознавания не меняется: бот показывает текст
  (`🎤 _«{text}»_`) и передаёт его в `_process` с меткой `[🎤 Голосовое]`.

### 4.3. Видеокружочки (новый `handle_video_note`)

- Новый хендлер, зарегистрированный на `filters.VIDEO_NOTE`
  (добавить регистрацию ДО catch-all хендлера `handle_other`).
- Логика зеркалит `handle_voice`: статус «🎥 Распознаю кружочек... ⏳»,
  скачивание MP4, отправка в тот же `transcribe` (имя файла `note.mp4`),
  показ текста, передача в `_process` с меткой `[📹 Кружочек]`.
- Без сессии — тот же ответ `_no_session_reply`, как у остальных хендлеров.
- Подсказку в `handle_other` дополнить: бот понимает «текст, голосовые,
  кружочки, изображения, PDF и ссылки».

### 4.4. Ошибки и краевые случаи

- **Слишком длинная запись:** если `voice.duration > 600` секунд (10 минут) —
  вежливый отказ («Запись длиннее 10 минут — расскажите короче или напишите
  текстом»), запрос к API не выполняется. Кружочки Telegram сам ограничивает
  одной минутой — отдельная проверка не нужна.
- **Ошибка API (сеть, 429, 5xx):** один повторный запрос; если и он упал —
  текущее сообщение «❌ Не удалось распознать — попробуйте ещё раз или
  напишите текстом». Ошибка логируется. Интервью и сессия не ломаются.
- **Пустая транскрипция** (тишина, шум): «🤔 Не расслышал — повторите,
  пожалуйста, или напишите текстом». В `_process` пустой текст не передаётся.
- Распознавание, как и сейчас, выполняется через `asyncio.to_thread`,
  чтобы не блокировать event loop.

### 4.5. Зачистка зависимостей

- Из `requirements.txt` удалить `SpeechRecognition` и `pydub`.
- Из `nixpacks.toml` удалить `ffmpeg` (использовался только для pydub).
- Из `main.py` удалить импорты/код, связанные с ними.

## 5. Что сознательно НЕ делаем (вне объёма)

- Фолбэк на второй движок распознавания — при отказе Groq пользователь
  просто пишет текстом; объёмы бота не оправдывают усложнение.
- Аудиофайлы, присланные документом (MP3/WAV и т.п.) — по-прежнему
  отклоняются с подсказкой.
- Диаризация, таймкоды, очереди задач, вебхуки — не нужны.

## 6. Критерии приёмки

1. Русское голосовое 30–60 секунд распознаётся с пунктуацией, без
   пропущенных фраз и искажённых слов (проверить на 3–5 реальных записях,
   включая запись с уличным шумом).
2. Видеокружочек распознаётся и попадает в интервью так же, как голосовое.
3. Ответ бота на минутное голосовое приходит не дольше ~5 секунд.
4. Голосовое длиннее 10 минут вежливо отклоняется без вызова API.
5. С неверным `GROQ_API_KEY` бот отвечает понятной ошибкой, интервью
   продолжает работать с текстом.
6. `SpeechRecognition`, `pydub` и `ffmpeg` отсутствуют в зависимостях,
   деплой на Railway проходит успешно.

## 7. Стоимость и лимиты (справочно)

- Бесплатный tier Groq покрывает объёмы бота с большим запасом
  (лимиты — тысячи секунд аудио в день).
- Платный tier, если понадобится: whisper-large-v3 ≈ $0.111 за час аудио
  (~10 ₽/час), turbo ≈ $0.04/час.
- Лимит размера файла 25 МБ — часовое голосовое OGG весит меньше, в
  практике бота недостижимо.
