# Дизайн-спека: Генератор упаковки для экспертов (Блок 1)

> Дата: 2026-06-23
> Источник идеи: сервис упаковки и автоворонки для экспертов (психологи, коучи, наставники).
> Исследование-основа: `research-packaging-funnel.md`

## 1. Контекст и границы

Большая цель — самосервисный сервис «полная автоворонка» для экспертов: упаковка продукта + живая страница + автору рассылка + кабинет. Это слишком много для одной спеки, поэтому цель разбита на под-проекты:

1. **Генератор упаковки** — онбординг + AI-генерация материалов. ← *эта спека*
2. Живая страница — хостинг лендинга/профиля по ссылке + сбор заявок.
3. Авторассылка — серия писем по собранным лидам.
4. Обвязка — кабинет, оплата, база лидов.

Зависимость: блок 1 создаёт контент → блок 2 публикует и ловит лидов → блок 3 догревает. Поэтому первым строим **блок 1**. Он ценен сам по себе: эксперт получает готовую упаковку, даже когда страницы и рассылки ещё нет.

**Эта спека описывает только блок 1.** Каждый следующий блок — свой цикл спека → план → реализация.

## 2. Что строим (первая версия)

Самосервисный веб-сервис. Эксперт проходит пошаговый онбординг и получает готовую упаковку из трёх материалов.

**В первой версии НЕТ:**
- входа/регистрации;
- оплаты;
- хостинга страниц и рассылок (это блоки 2–3).

**Но фундамент «взрослый»:** Next.js + реальная база данных, нормальная архитектура — чтобы блоки 2–4 дорастить, не переписывая.

Цель первой версии — **проверить спрос**: захотят ли эксперты этим пользоваться.

## 3. Материалы на выходе (3 этапа, строго по порядку)

1. 🎯 **Оффер / позиционирование** — стержень: кто, для кого, какой результат, чем отличается.
2. 📄 **Текст лендинга / профиля** — растёт из принятого оффера: заголовок, «о мне», услуги, отзывы, призыв.
3. ✉️ **Серия писем / прогрев** — 4 письма, ведут к покупке/на лендинг.

**Последовательная выдача:** открыт только текущий этап. Пока эксперт не «примет» текущий материал — следующий под замком (🔒) с понятной подписью, *почему* он закрыт (каждый строится на принятом предыдущем). Это гарантирует, что этап не пропустят.

У каждой готовой карточки — кнопки **«Копировать»** и **«Ещё вариант»** (пересоздать).

## 4. Поток и экраны

```
Верхнее меню (Создать · Как это работает · Примеры)
        │
        ▼
1. Онбординг — 5–7 коротких вопросов, по одному на экран,
   с примерами-плейсхолдерами, прогресс-бар
        │
        ▼
2. Генерация — текст печатается по словам (стриминг),
   не пустой экран с крутилкой
        │
        ▼
3. Последовательная выдача 3 карточек:
   Оффер → (принять) → Лендинг → (принять) → Письма
   у каждой: Копировать / Ещё вариант
```

**Приёмы простоты (из исследования):** один экран без лишней навигации, примеры прямо в полях, кнопки названы по результату («Принять оффер → к лендингу»), результат сразу с кнопкой «Копировать», стриминг текста.

### Черновик вопросов онбординга (7 шт., уточняется при реализации)

1. **Чем ты занимаешься?** (ниша) — *напр.: «Психолог, работаю с тревогой и выгоранием»*
2. **Кому ты помогаешь?** (аудитория) — *напр.: «Мамы 30–40 лет в декрете»*
3. **Какой результат получает клиент?** (главный итог, 5–8 слов) — *напр.: «Выходят из выгорания за 6 недель»*
4. **Как ты это делаешь?** (метод/формат) — *напр.: «6-недельная программа мягких ежедневных шагов»*
5. **Чем ты отличаешься от других?** (отстройка) — *напр.: «Работаю по протоколу, а не по наитию»*
6. **Что ты продаёшь и за сколько?** (продукт, цена) — *напр.: «Консультации + курс, 15 000 ₽»*
7. **В каком тоне общаешься?** (голос бренда) — *напр.: «Тепло, по-человечески, без эзотерики»*

## 5. Техническая архитектура

### Принцип: храним в РФ, генерим лучшей моделью, наружу — только обезличенный бриф

- **Серверы и база — в РФ.** Приложение и БД на российском хостинге. Все данные хранятся в России → закрывает 152-ФЗ (локализация персональных данных).
- **Генерация — топовой моделью (Claude) через ProxyAPI.** ProxyAPI — российское юрлицо, оплата рублями. Качество упаковки максимальное (российские модели качество убивают — отвергнуто сознательно).
- **Минимизация данных.** В модель уходит только маркетинговый бриф об оффере, без персональных данных. В v1 нет email/логина — регулируемые перс. данные за границу не уходят. Когда позже добавим кабинет/почты — эти данные остаются в российской БД и в модель не передаются.

> Оговорка: финальную юридическую схему свериться с профильным юристом. Описанное — общепринятый компромисс «качество + 152-ФЗ», не юридическое заключение.

### Стек

| Слой | Выбор |
|---|---|
| Приложение + UI | Next.js |
| Генерация AI | Vercel AI SDK (стриминг) → ProxyAPI (Claude) |
| База данных | PostgreSQL на российском сервере |
| Хостинг | Российский: начать с нашего VPS `195.2.85.114`, альтернатива — Яндекс Облако |
| Оплата (позже, блок 4) | ЮKassa |

### Что хранит база в v1

Минимум: сгенерированные упаковки по анонимному id сессии (чтобы результаты не терялись и для будущей аналитики «что генерируют»). Без персональных данных.

## 6. Дизайн-направление

- Тёплые пастельные карточки (как у Notion): оффер — лавандовый, лендинг — голубой, письма — мятный.
- Акцент — индиго `#5E6AD2` на главных кнопках.
- Много воздуха, тени вместо рамок, скругления 12px.
- Текст печатается по словам.
- **Шрифт — открытый вопрос.** Inter заезжен (отмечено дизайн-хуком); характерный шрифт выберем на этапе визуала, не на этапе потока.

## 7. Обработка ошибок

- **AI недоступен / долгий ответ:** понятное сообщение + кнопка «Повторить». Не пустой экран с бесконечной крутилкой.
- **Пустой/слишком короткий ответ онбординга:** мягкая подсказка («добавь пару слов»), не жёсткий блокер.
- **Ошибка при «Ещё вариант»:** прошлый результат остаётся на экране, не теряется.

## 8. Критерии успеха (проверяемые)

1. Эксперт проходит онбординг от первого вопроса до конца.
2. Каждый из 3 этапов генерится и после «принятия» разблокирует следующий.
3. Последовательность соблюдается: заблокированный этап нельзя открыть раньше времени.
4. «Копировать» кладёт текст в буфер; «Ещё вариант» пересоздаёт.
5. Стриминг: текст появляется по словам, а не разом после паузы.
6. Ошибки AI обрабатываются понятным сообщением и повтором.
7. Бриф уходит в модель без персональных данных; данные хранятся на российском сервере.

## 9. Открытые вопросы (решить при реализации)

- Точная формулировка 5–7 вопросов онбординга (черновик в §4).
- Хостинг: наш VPS vs Яндекс Облако (рекомендация — начать с VPS).
- Выбор шрифта (этап визуала).
- Нужен ли минимальный экран согласия на обработку данных уже в v1 (вероятно да, простая галочка + политика).
