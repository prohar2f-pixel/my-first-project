# Дизайн: генерация новых фото реального человека (PhotoMaker)

Дата: 2026-06-22
Проект: image-gen (бэкенд `image-gen-api`, фронтенд `image-gen/`)

## Цель

Дать пользователю возможность загрузить несколько фотографий реального
человека и получать его новые фотографии в разных образах, одежде и
локациях — без реальной фотосессии.

## Выбранный подход

Путь A — **Runware PhotoMaker** (`taskType: "photoMaker"`).
- Без обучения модели: до 4 референс-фото + промпт → новые изображения с
  тем же лицом.
- Работает только с SDXL-моделями (конкретный AIR-идентификатор модели
  выбирается при реализации).
- Путь B (обучение LoRA на внешнем сервисе) отложен на будущее как
  «премиум-режим» и в этот спек не входит.

Источники: [PhotoMaker API | Runware Docs](https://runware.ai/docs/image-inference/photomaker),
[Model Upload API | Runware Docs](https://runware.ai/docs/image-inference/model-upload),
[Image inference API reference | Runware Docs](https://runware.ai/docs/image-inference/api-reference).
Подтверждено: Runware НЕ обучает LoRA (только загрузка готовых моделей),
поэтому используем PhotoMaker.

## Пользовательский сценарий

1. На странице генерации вверху — переключатель режимов:
   «Текст → фото» (существующий) и «Фото человека → новые фото» (новый).
2. В новом режиме пользователь: загружает до 4 фото (с превью), пишет
   промпт, жмёт «Сгенерировать».
3. Результат показывается в той же области, что и обычные генерации,
   и сохраняется в общую историю/галерею.

## Изменения в бэкенде (`image-gen-api`)

### `runware.py` — новая функция
```
async def generate_person_images(
    prompt: str,
    input_images: list[str],   # data URI (base64) каждого фото
    width: int,
    height: int,
    count: int,
    style: str = "Photographic",
    strength: int = 20,
) -> list[str]
```
- Формирует payload с `taskType: "photoMaker"`, полями `inputImages`,
  `style`, `strength`, `positivePrompt`, `width`, `height`,
  `numberResults`, `steps`, `CFGScale`, `outputFormat: "WEBP"`,
  `model` (SDXL AIR id).
- Автоматически вставляет слово-триггер `img` в `positivePrompt`, если
  его там нет (требование PhotoMaker). Логика: если в промпте нет
  отдельного токена `img`, добавить его (например, `"<prompt>, img"` или
  после класс-слова — уточнить при реализации по результату).
- Возвращает список URL картинок (как существующая `generate_images`).

### `main.py` — новый эндпоинт
```
POST /api/generate-person
body: {
  prompt: str,
  input_images: list[str],   # 1..4 data URI
  width: int = 1024,
  height: int = 1024,
  count: int = 1,
}
```
- Авторизация: тот же `get_current_user`, что у `/api/generate`.
- Кредиты: списываются так же — `count * CREDITS_PER_IMAGE`, та же
  проверка 402 для не-админов.
- Валидация: `1 <= len(input_images) <= 4`; если 0 — 422; если >4 — взять
  первые 4 (фронт это тоже контролирует).
- Сохранение: переиспользуем модель `Generation`. В поле `settings`
  добавляем `{"mode": "person"}`, чтобы отличать от обычной генерации.
  Сами референс-фото в БД НЕ сохраняем (только результат).
- Ответ: `{ id, image_urls, credits }` — как у `/api/generate`.

### Размер запроса
До 4 фото в base64 могут быть большими. Поставить разумный лимит на
размер тела запроса/фото (например, ужимать на фронте до ~1024px перед
отправкой). Детали — на этапе реализации.

## Изменения во фронтенде (`image-gen/index.html`)

- Переключатель режимов (две кнопки) вверху блока генерации.
- Режим «Текст → фото»: без изменений.
- Режим «Фото человека → новые фото»:
  - `<input type="file" accept="image/*" multiple>` — до 4 файлов.
  - Превью-миниатюры выбранных фото с возможностью убрать лишние.
  - Поле промпта (как сейчас).
  - Кнопка «Сгенерировать» → `POST /api/generate-person` с фото в base64.
- Перед отправкой фото читаются в data URI (FileReader) и при
  необходимости ужимаются по размеру.
- Результат и список кредитов обновляются той же логикой, что и сейчас.

## Что НЕ трогаем

Вход (`login.html`), админка (`admin.html`), обычная текстовая генерация,
система кредитов, модели БД (кроме добавления флага в `settings`).

## Обработка ошибок

- Нет загруженных фото → кнопка неактивна + подсказка.
- Загружено >4 → берём первые 4, предупреждаем пользователя.
- Недостаточно кредитов → 402 (как сейчас).
- Ошибка Runware → понятное сообщение пользователю, кредиты не
  списываются при неуспехе.

## Тестирование

- Юнит-тест эндпоинта `/api/generate-person`: валидация количества фото
  (0 → ошибка, 1..4 → ок, проверка списания кредитов) с замоканным
  вызовом Runware.
- Ручная проверка: загрузить 1–4 реальных фото, сгенерировать, убедиться
  что лицо узнаваемо и результат попал в историю/галерею.

## Открытые вопросы для реализации (не блокируют спек)

- Точный AIR-идентификатор SDXL-модели для PhotoMaker.
- Точная вставка триггера `img` (позиция в промпте) — подобрать по
  качеству результата.
- Предел размера/ресайз загружаемых фото.
