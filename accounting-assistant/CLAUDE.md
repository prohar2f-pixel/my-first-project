# CLAUDE.md — Accounting Assistant для бухгалтера

**Проект:** Веб-ассистент для проверки НДФЛ и консультаций по налогам в строительстве.  
**Пользователь:** Один бухгалтер (внутри сети компании на VPS 195.2.85.114)  
**Стек:** React + FastAPI + OpenRouter + SQLite/PostgreSQL

---

## 1. Думай перед кодом

- **Приоритет 1:** Проверка НДФЛ из загруженных зарплат
- **Приоритет 2:** Консультации по налогам в РФ (строительство)
- **Приоритет 3:** История диалогов и анализ файлов
- Не добавляй функции «на будущее» — только MVP

---

## 2. Простота превыше всего

- Один пользователь = простая аутентификация (пароль в env)
- Загрузка Excel вручную (пока нет 1C API)
- Минимум функций в первой версии
- Нет боли с микросервисами, сложными БД, кэшированием на уровне приложения

## 3. Хирургические изменения

- Завтра: добавим 1C API когда админ настроит

## Архитектура (краткая)

### Frontend
- React с простым интерфейсом (чат + файлозагрузка)
- TypeScript
- Никаких heavy-фреймворков (не Material UI, не Tailwind на весь проект)

### Backend
- FastAPI (Python)
- OpenRouter API для ИИ
- SQLite для MVP (PostgreSQL позже если нужна масштабируемость)
- Промпты для НДФЛ-проверки и налоговых консультаций

### Данные
- Excel → парсим с помощью openpyxl/pandas
- Кэш справочников (налоговые ставки) в БД
- История диалогов в БД

### Безопасность
- Пароль в .env
- Шифрование конфиденциальных данных (зарплаты) если критично
- HTTPS на VPS
- Резервные копии БД автоматические
- Настоящие ключи — только в `.env` (он в `.gitignore`). В `.env.example` — только заглушки, никогда реальные значения.
- Ключ, попавший хоть раз в коммит, считается скомпрометированным — меняй его, а не просто удаляй строку.

## Ключевые риски и как их снять

1. **1C API не готова месяцами** → Инструкция для админа готова, можно помочь удалённо
2. **Конфиденциальность зарплат** → Хранишь на локальном VPS, шифруешь если надо
3. **Налоги устаревают** → Обновляй базу знаний в промптах 1-2 раза в год
4. **1C упадёт** → Кэш спасает, ассистент работает автономно
