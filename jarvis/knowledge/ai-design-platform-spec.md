# AI Design Platform — Спецификация

## Что это

Личная веб-платформа для автоматизации разработки дизайна сайтов.
Один экран — три суперсилы: генерация дизайна через ИИ, обработка медиа через Runware, публикация в Tilda.

**Для кого:** только для себя  
**Цель:** сократить цикл ChatGPT → Figma → Tilda с 2-4 недель до 1-2 дней

---

## Три боли и как решаем

| Боль | Сейчас | После платформы |
|------|--------|-----------------|
| ChatGPT → Figma | Вручную, 2 недели | ИИ генерирует структуру → Figma API создаёт фреймы |
| Медиа-обработка | Разные сервисы | Всё через Runware, одна страница |
| Figma → Tilda | Вручную по блокам | HTML-экспорт → Tilda API / Zero Block |

---

## Архитектура платформы

```
[Браузер — одна страница]
        │
        ├── ИИ-чат (ChatGPT/Claude API)
        │     └── генерирует описание дизайна + структуру
        │
        ├── Figma-модуль (Figma REST API)
        │     ├── создать фрейм по описанию
        │     ├── читать текущий дизайн
        │     └── экспортировать в HTML
        │
        ├── Runware-модуль (Runware API)
        │     ├── убрать фон
        │     ├── улучшить качество фото
        │     ├── сгенерировать изображение
        │     ├── AI-аватар + сцены
        │     ├── генерация видео
        │     └── генерация иконок
        │
        └── Tilda-модуль (Tilda API)
              ├── создать/обновить страницу
              └── вставить HTML в Zero Block
```

## Что строим по этапам

### Этап 0 — Регистрация и ключи (до старта)

Нужно получить:
- [ ] Runware API ключ → runware.ai → Sign Up → API Keys
- [ ] Figma Personal Access Token → figma.com → Settings → Security
- [ ] Tilda API ключ → tilda.cc → Личный кабинет → API
- [ ] OpenAI или Anthropic API ключ (для генерации описаний дизайна)

### Этап 1 — Runware медиа-инструмент *(неделя 1)*

Простая HTML-страница в браузере:
- Поле для ввода Runware API ключа (сохраняется локально)
- Вкладки: Фон | Качество | Изображение | Аватар | Видео | Иконки
- На каждой вкладке: загрузи файл + параметры + кнопка → результат

**Почему первым:** никакой сложной интеграции, сразу полезен, покрывает 90% работы с медиа

### Этап 2 — Figma-генератор *(неделя 2-3)*

- Поле: описание дизайна текстом
- ИИ преобразует описание в структуру (блоки, цвета, шрифты)
- Figma API создаёт фреймы с нужными слоями
- Результат: открываешь Figma — там готовый редактируемый макет

**Ограничение:** сложные анимации и нестандартные элементы — придётся доделывать руками

### Этап 3 — Tilda-публикатор *(неделя 4)*

- Кнопка "Экспорт в Tilda" берёт HTML из Figma Dev Mode
- Отправляет в указанную страницу Tilda через API
- Вставляет в Zero Block или создаёт новую страницу

**Ограничение:** Tilda API не позволяет управлять каждым блоком в точности — используем Zero Block как контейнер

### Этап 4 — Объединение *(неделя 5+)*

- Единый воркфлоу: описание → ИИ → Figma → обработка медиа → Tilda
- Сохранение проектов (какой дизайн с каким Tilda-сайтом связан)

## Технологии

| Часть | Технология | Почему |
|-------|-----------|--------|
| Интерфейс | HTML + CSS + JS (без фреймворков) | Просто открыть в браузере, не нужна установка |
| Хостинг | GitHub Pages или локально | Уже умеешь, бесплатно |
| API вызовы | Fetch из браузера | Не нужен сервер для большинства операций |
| Секреты | localStorage | Ключи хранятся только у тебя |
| Runware | runware.ai WebSocket API | Быстрее чем REST для генерации |

---

## Что точно НЕ входит в скоп

- Многопользовательский режим (только для тебя)
- Мобильная версия платформы
- Хранение файлов на сервере (всё локально или через API третьих сторон)
- Полная автоматизация Figma↔Tilda без ручного шага (технически невозможно через Tilda API)

---

## Риски

| Риск | Вероятность | Что делаем |
|------|------------|-----------|
| Figma API не позволяет создать сложный дизайн | Средняя | Начнём с базовых элементов, расширим |
| Tilda API не даёт нужный контроль | Высокая | Используем Zero Block как обходной путь |
| Runware не поддерживает нужную модель | Низкая | У них тысячи моделей, найдём замену |
