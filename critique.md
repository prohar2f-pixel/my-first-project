# Критика идеи и исследования + Рекомендации для спецификации

> Три независимых агента провели анализ. Это честный разбор до строчки кода.

---

## ЧАСТЬ 1: Критика идеи

### 1.1 Реально ли идея решает боль?

**Частично — и это проблема.**

Боль фрилансера — не "нет времени". Боль глубже: нет системы, нет привычки, нет понимания зачем. Агент не лечит причину. Реальный сценарий:

1. Агент генерирует контент-план
2. Ты смотришь посты — "ну окей"
3. Согласовываешь, потому что лень переделывать
4. Выходят безликие посты про "тренды веб-разработки"
5. Охваты нулевые, потому что нет личного голоса
6. Через 2 недели перестаёшь открывать согласования
7. Агент постит в пустоту

**Агент решает проблему публикации, но не решает проблему качества.** А именно качество конвертирует в клиентов.

Главный вопрос, который нужно ответить до строчки кода: **"Что конкретно изменится через 3 месяца, и я скажу что агент работает?"**

---

### 1.2 Лишние функции

| Функция | Вердикт | Причина |
|---|---|---|
| Яндекс Дзен (автопубликация) | **Выбросить** | Официального API нет. Только браузерная автоматизация — хрупко, нарушает ToS |
| Видеосценарии | **Выбросить** | "По необходимости" = никогда. Усложняет без ROI |
| Мониторинг конкурентов в v1 | **Урезать** | Звучит солидно, сломается через месяц. Оставить только RSS-новости |
| Автопостинг в Instagram Stories/Reels | **Отложить** | Только Feed/Reels через официальный API, нужен бизнес-аккаунт |

---

### 1.3 Противоречия в идее

**Конфликт 1: Автономность vs контроль**
"Агент сам составляет план" + "показывает на согласование" + "я добавляю вводные" — так кто управляет повесткой? Если ты каждый раз правишь — это костыль. Если не правишь — посты обезличены.

**Конфликт 2: Мониторинг конкурентов vs личный бренд**
Фрилансер продаёт себя. Копировать тактику конкурентов убивает уникальность. Зачем следить за конкурентами, если продаёшь личную экспертизу?

**Конфликт 3: "Публикует во все соцсети сразу"**
Telegram, Instagram и ВКонтакте — разные аудитории, алгоритмы, форматы. Один пост для всех = везде средне. Нужна адаптация, а не копирование.

**Конфликт 4: Автопубликация без предпросмотра**
После согласования агент постит сам. Ты не видишь финальный вид на платформе до публикации. Один баг в форматировании — и вышел кривой пост.

---

### 1.4 Технические риски

**Instagram Graph API:**
- Требует Business/Creator аккаунт + Facebook Business Manager
- Личные аккаунты — не поддерживаются вообще
- Лимит 200 вызовов в час, при нарушениях — бан без предупреждения
- Stories через API недоступны

**ВКонтакте API:**
- Токены протухают, нужен refresh
- Алгоритм VK давит органику в пользу рекламы

**Яндекс Дзен:**
- Официального API для публикации нет (проверено)
- Только браузерная автоматизация — нарушение ToS + хрупко

**Общий риск:** ты строишь на чужих API. Любое из них может измениться — и часть функционала отвалится навсегда. Это поддержка, а не "написал и забыл".

---

### 1.5 Что забыли учесть

**Визуал — полностью отсутствует в идее**
Посты без картинок в Instagram не публикуются физически. В ВКонтакте и Telegram визуал влияет на охваты. Откуда берутся изображения?

**Хэштеги**
Не упомянуты. В Instagram влияют на охваты. Кто подбирает? Как обновляются?

**Обратная связь**
Нет механизма: агент не знает что пост провалился. Без петли обратной связи — агент повторяет одни и те же ошибки вечно.

**Повторяемость контента**
Через 4–6 недель агент начнёт крутить одни темы. Нет механизма отслеживания уже закрытых тем.

**Сезонность и жизнь**
Агент не знает, что ты был на конференции, взял интересный проект или выгорел. Контент-план на месяц не учитывает реальность.

---

### 1.6 Система памяти — главный пробел

В идее не описана вообще. Без памяти агент — это GPT с кнопкой публикации.

Минимально нужно:
- Голос бренда (стиль, запрещённые слова, тон)
- База опубликованных постов с темами
- Что зашло, что нет (по платформам)
- Текущая цель (продвижение услуги X в этом месяце)

Это отдельный архитектурный слой, не "настроить за час".

---

### 1.7 Реализм сроков

**"2–4 недели" — иллюзия.** Реальная оценка:

| Компонент | Срок |
|---|---|
| Telegram-бот с кнопками согласования | 3–5 дней |
| Генерация контента через LLM | 4–7 дней |
| Instagram API + авторизация | 3–5 дней |
| ВКонтакте API + refresh токенов | 2–3 дня |
| RSS-мониторинг + парсинг | 3–5 дней |
| Система памяти (базовая) | 5–7 дней |
| Планировщик публикаций | 2–3 дня |
| Тестирование и баги | 5–7 дней |
| **Итого** | **8–12 недель** |

За 2–4 недели реален только MVP: Telegram + VK, без памяти, без мониторинга.

## ЧАСТЬ 3: Рекомендации для спецификации

### 3.1 Система памяти (приоритет #1)

**Что хранить:**
- `published_posts` — тема, платформа, дата, реакция аудитории
- `brand_voice` — примеры постов с оценкой "мой стиль / не мой"
- `used_topics` — список закрытых тем (скользящее окно 60 записей)
- `user_preferences` — запрещённые слова, тон, бизнес-цель
- `competitor_signals` — что нашли, дата, платформа

**Как хранить (v1 — просто):**
- Google Sheets — `published_posts` и `used_topics` (пользователь видит и редактирует)
- JSON-файл на сервере — `brand_voice`, `user_preferences`
- Векторная БД (Chroma/mem0) — только v2, когда 100+ постов

**Обновление:**
- После каждой публикации — запись в Sheets автоматически
- После одобрения/отклонения — обновление `brand_voice`
- Раз в неделю — бот отправляет "дайджест": темы за месяц

---

### 3.2 Голос бренда

**При онбординге собрать три вещи:**
1. 5–7 лучших своих постов (агент извлекает паттерны)
2. "Я пишу для..." — описание аудитории своими словами
3. Антипримеры — 2–3 поста конкурентов, которые не нравятся

**System prompt для голоса бренда** (`brand_voice_prompt.txt`):
```
Ты пишешь посты от имени [имя]. 
Стиль: [выжимка из примеров].
Не используй: [список запрещённых слов].
Аудитория: [описание].
Примеры хороших постов: [3 лучших примера].
Бизнес-цель: [что должен сделать читатель].
```

Команда `/voice` в боте — пользователь редактирует этот файл напрямую.

---

### 3.3 Контент-план

**Генерация тем — три шага:**
1. Читает `used_topics` — список уже закрытых углов
2. Собирает сигналы: RSS (vc.ru, habr.com, tproger.ru), Google Trends
3. Генерирует 7–10 идей с обоснованием

**Структура недели:**
- 2 поста "польза" (кейс, туториал)
- 1 пост "личное" (мнение, история)
- 1 пост "продающий" (услуга, портфолио)
- 1 пост "реакция на тренд"

**Антидублирование:** перед генерацией промпт включает: "Темы, которые уже были: [список]. Не предлагай похожее."

---

### 3.4 Мониторинг конкурентов (реалистичный v1)

| Что мониторить | Инструмент | Сложность |
|---|---|---|
| Telegram-каналы конкурентов | Telethon (публичные) | Средняя |
| VK публичные страницы | VK API | Низкая |
| Сайты конкурентов (блоги) | RSS / sitemap.xml | Низкая |
| Новости ниши | RSS habr/vc.ru | Низкая |

**Не трогать:** Instagram конкурентов (Meta заблокирует), TikTok (нет API).

---

### 3.5 Публикация

| Платформа | Путь | В v1? |
|---|---|---|
| Telegram-канал | Bot API | ✅ Да |
| ВКонтакте | VK API | ✅ Да |
| Instagram | Meta Graph API (бизнес-аккаунт) | ⚠️ Да, только Feed/Reels |
| Яндекс Дзен | Нет API | ❌ Нет — только готовит текст, публикуешь сам |

**Архитектура публикатора:**
```
APScheduler → JSON-очередь → publisher (адаптеры per platform) → лог в Sheets
```
Никакого Celery/Redis в v1. Один пользователь = простая очередь.

---

### 3.6 Согласование

**Флоу:**
```
Генерация → Бот отправляет пост + кнопки:
[✅ Опубликовать] [✏️ Переделать] [🗑 Отклонить] [📅 Перенести]
→ "Переделать" → пользователь пишет правку → агент перегенерирует
→ Максимум 2 итерации на один пост
```

**Таймаут:**
- 24 часа — напоминание
- 48 часов — пост уходит в "отложен" (не публикуется)

---

### 3.7 Что НЕ делать в v1

1. **Яндекс Дзен авто-публикация** — нет API, хрупко, нарушает ToS
2. **Сбор аналитики engagement** — сложно, много токенов. В v2
3. **Векторная БД** — избыточно до 100 постов
4. **Мультипользовательность** — один агент для одного человека
5. **Генерация изображений** — пользователь добавляет картинку сам
6. **TikTok** — нет стабильного пути публикации
7. **Автопубликация без согласования по умолчанию**

---

### 3.8 Критические риски

**Риск 1: Деградация голоса бренда**
Агент войдёт в петлю самоподтверждения — посты будут "правильными" но не твоими. Решение: только ты оцениваешь стиль, агент сам себя не оценивает.

**Риск 2: Баны токенов платформ**
VK и Meta банят при подозрительной активности. Решение: случайный сдвиг времени публикации ±15 минут, rate limiting, инструкция по ручному обновлению токенов.

**Риск 3: Контент без бизнес-цели**
Агент будет генерировать "правильные" посты, которые не конвертируют. Решение: при онбординге обязательно — "какое действие должен совершить читатель?" — и это в system prompt.

**Риск 4: Переполнение памяти тем**
Через 3 месяца 200 записей → странные темы. Решение: скользящее окно — только последние 60 записей для антидублирования.

**Риск 5: Пользователь бросает согласование**
Самый реальный способ гибели проекта. Если согласование занимает > 30 секунд — забиваешь. Решение: кнопки прямо в Telegram, превью в том же сообщении, одно нажатие для одобрения.

## Итоговый вердикт

**Жизнеспособная v1:** Telegram-бот генерирует посты для Telegram-канала и ВКонтакте, показывает на согласование, публикует. Память = Google Sheets + JSON-файл. Голос бренда = system prompt из онбординга.

**Что выбросить из v1:** Instagram Stories, Дзен (авто), видеосценарии, мониторинг конкурентов (оставить только RSS).

**Реальный срок MVP:** 3–4 недели для Telegram+VK без мониторинга. 8–12 недель для полной версии.
